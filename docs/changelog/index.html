September 28, 20260.3.0

A changelog page like the best product teams publish

The page now reads like Linear's or Raycast's changelog, and Shiplog adds new releases to your existing changelog in its own format, in any major language.

A redesigned changelog page

Each release now has a headline, a short intro and an optional hero image, with the date and version in a column beside it. Anything readers must do is collected in one Action required box at the top. The biggest changes get their own section with a heading, text, screenshot and links, and everything else is listed compactly under New, Improvements and Fixes. Audience labels show who a change is for.

How a release is shown →

Affects: People using the skill in Claude Code

New releases added to your existing CHANGELOG.md

If your repository already has a hand-written CHANGELOG.md, Shiplog now adds each new release above the newest one, in the same format: the same headings, date style, section names, bullets and pull request links. It works with Keep a Changelog, conventional-changelog and custom formats. Existing entries are never changed, and a release is never added twice.

Affects: People using the skill in Claude Code

New

  • Tested across the major programming languages

    Shiplog now detects your project from package.json, pyproject.toml, go.mod, pom.xml, Gradle settings, .NET project files, composer.json, gemspecs and Cargo.toml. It finds changelogs named HISTORY.md, CHANGES or NEWS, understands underlined headings, label-style sections and changelogs without sections, and reads tag styles like 4.18.2 turning into v5.2.1. Tested on real JavaScript, TypeScript, Python, Go, Java, Kotlin, C#, PHP, Ruby and Rust projects.

    Affects: People using the skill in Claude Code

  • Headlines, highlights and images in release files

    Release files can now have a title headline, a longer intro, a hero image, and entries marked as highlights with their own screenshot. All are optional; existing release files keep working, and new features are highlighted automatically.

    Affects: People using the skill in Claude CodeShiplog contributors

Improvements

  • A simpler filter bar

    The filter box is now a single bar: choose an audience, show only changes that need action, or search.

    Affects: People using the skill in Claude Code

Fixes

  • Stronger contrast for secondary text

    Section labels and counts on the changelog page now meet WCAG AA contrast in light mode.

    Affects: People using the skill in Claude Code

September 28, 20260.2.0

Slack announcements, faster drafting, archive pages and audience feeds

Action required

  • Python 3.10 or newer

    If you run Shiplog or its CI workflow on Python 3.8 or 3.9, switch to Python 3.10 or newer.

    Affects: People using the skill in Claude CodeMaintainers of the Shiplog CI workflow

New

  • Announce releases in Slack

    After a release is published, Shiplog can post it to one or more Slack channels. Each channel only gets the changes for its audiences, and action-required changes come first with their deadline. You see a preview of every message and nothing is sent until you confirm. Webhook URLs and tokens stay in environment variables or CI secrets, never in the repository.

    Slack setup guide

    Affects: People using the skill in Claude CodeMaintainers of the Shiplog CI workflow

  • Use Shiplog in any repository

    Install the skill into a repository with one command and commit it, so everyone on the team gets it in Claude Code. Setup detects the app name from package.json, pyproject.toml, Cargo.toml, go.mod or the git remote, and the tag style from existing tags. Commands work from any folder in the repository.

    Affects: People using the skill in Claude Code

  • Import an existing CHANGELOG.md

    Ask Claude to import your Keep a Changelog file and each version becomes a Shiplog release. Old entries don't say who is affected, so every imported entry is marked for review, and the validator lists them until you confirm the impact.

    Affects: People using the skill in Claude Code

  • A feed for each audience

    Besides the main feed, each audience now gets its own Atom feed with only the changes that affect it, plus changes for everyone. The changelog page links to all of them, so admins can subscribe to admin changes only.

    Affects: People using the skill in Claude Code

  • Translate the changelog page and get link previews

    Every label on the page, including month names and the date format, can be translated in the config. Pages now include Open Graph and canonical tags, so links shared in chat or social apps show a proper preview.

    Affects: People using the skill in Claude Code

  • Autocomplete for release files in your editor

    Release files and the config now point to a JSON Schema, so editors like VS Code suggest field names and flag mistakes while you type.

    Affects: People using the skill in Claude CodeShiplog contributors

Improvements

  • Releases are drafted faster, with fewer questions

    Claude now reads a compact one-line-per-change summary instead of every commit in full, and asks all its questions about impact in one message. If you already gave the version or impact details, it doesn't ask again. When the GitHub CLI is available, pull request titles, descriptions and labels are fetched in a single request.

    Affects: People using the skill in Claude Code

  • Changes are grouped by pull request

    Repositories that use merge commits or squash merges now get one suggested entry per pull request, titled with the pull request's title, instead of one per commit. Previously the pull request titles in merge commits were skipped.

    Affects: People using the skill in Claude Code

  • Older releases move to yearly archive pages

    The main changelog page now shows the latest 20 releases. Older releases are on one page per year, linked at the bottom of every page. Feeds and CHANGELOG.md link to the right page. Links to an older release on the main page now land on the main page without jumping to it; set page_size to 0 in the config to keep everything on one page.

    Affects: People using the skill in Claude Code

  • Python 3.10 or newer Action required

    Shiplog is now tested on Python 3.10 through 3.13. Python 3.8 and 3.9 are no longer supported.

    Affects: People using the skill in Claude CodeMaintainers of the Shiplog CI workflow

  • More helpful validation messages

    Validation messages now name the file and the entry title, so problems are easy to find. The validator also warns when the newest release has a deadline that has passed, and when a deprecation doesn't say what to use instead.

    Affects: People using the skill in Claude CodeMaintainers of the Shiplog CI workflow

  • CI workflow template reads full history and can post to Slack

    New workflows fetch the full git history and tags, and include an optional step that announces tagged releases in Slack. Existing workflows keep working. To get the new template and scripts, run the setup again with the force option.

    Affects: Maintainers of the Shiplog CI workflow

Fixes

  • The changelog page no longer changes on every render

    Pages used to include the date they were built, so rendering unchanged releases on another day produced a diff. The footer now shows the latest release date, and re-rendering gives identical files.

    Affects: People using the skill in Claude CodeMaintainers of the Shiplog CI workflow

  • Better version suggestions

    After a pre-release such as 1.2.0-beta.1, the suggested version is now 1.2.0 instead of 1.2.1 or 1.3.0. First releases are suggested as 0.1.0, tags on other branches are ignored, and shallow CI checkouts get a clear message instead of a wrong range.

    Affects: People using the skill in Claude CodeMaintainers of the Shiplog CI workflow

  • Fewer false warnings about jargon

    Phrases like "our #1 priority", product names that contain words such as Hotfix, and standards like UTF-8 or ISO-8601 no longer trigger warnings. You can also list accepted terms in the config.

    Affects: People using the skill in Claude Code

  • Your hand-written CHANGELOG.md is never overwritten

    Shiplog used to replace an existing CHANGELOG.md the first time it rendered. Now it leaves a hand-written file alone and offers to import it; once imported, the old entries carry over into the generated file.

    Affects: People using the skill in Claude Code

  • First releases in repositories without tags

    Without version tags, Shiplog now asks where the release starts instead of summarizing the whole history, uses the version in your package manifest as the starting point, and warns when you're on a feature branch rather than the main branch.

    Affects: People using the skill in Claude Code
